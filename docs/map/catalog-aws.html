System map · a part

the catalog on AWS

What is the catalog made of in AWS, and what talks to what?

The shared catalog in the team's AWS account: the API on Lambda behind CloudFront, versions in DynamoDB, files in S3, a search file kept up to date by an indexer. Each version is reviewed as it is published. Only the GitHub logins the deployment lists may sign in.

B27 Search matching built

a search ranks by any word; skills that match every word are listed as matches, and skills that share only some words are listed apart, under "Not matches"; common words of an ask are ignored, a small list of synonyms is in the configuration, and words in a skill's name count more.

Chosen over every word must match

Why The Assistant sends several words at once; requiring all made it loop 3–13 times, while listing partial matches apart keeps "nothing matches" honest

Use-case steps through the catalog on AWS

  1. 1publish, step 5: v1 goes into the catalog, with its fingerprint and its review; a skill missing a name, description or body is refused, and nothing is stored
  2. 2discover, step 3: The catalog finds release-note-draft; when nothing fits, it says so, and shows the closest only as close
  3. 3retrieve, step 3: Every file of v1 is fetched, and checked against its fingerprint
  4. 4version, step 4: v2 is stored; v1 stays, and the history shows both
  5. 4version, step 5: Developer 2's list shows ↑ v2 available
  6. 5held update, step 3: v2 is fetched
  7. 6setup, step 3: In AWS: skills-catalog login signs in with GitHub once (on one machine there is nothing to sign in to)
