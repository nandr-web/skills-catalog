Skills Catalog

What is the system made of, and which parts can be swapped?

The architecture · on one machine and in AWS, with what's planned

Built around contracts, so each side can be swapped.

skills-catalog calls the API; the catalog's rules call their ports. What plugs into each sits beside it: on one machine on the left, in AWS on the right.

  • ⊐ ⊏ a contract: an interface in the code that the rest is written against
  • — from a contract: what plugs into it, checked in the code (it implements the contract)
  • A contract's shared tests run the same on both sides: on the local adapters and on the AWS ones (against an AWS stand-in). A new backend plugs in by passing them. Proven so far: the API, Storage, SearchIndex, Reviewer.
  • Orange, “no shared tests yet”: Events and Identity have no shared suite, so swapping their side isn't shown to work
  • Hatched, dotted, PHASE n · PLANNED: not built yet; n is the phase of the requirements that build it
  • Shaded, not ours: another company's part

API function

CloudFront · HTTP API · Lambda

In AWS, skills-catalog's client (core/src/remote) calls the same operations over HTTPS (SKILLS_CATALOG=https://…): CloudFront, then the HTTP API, then the API function, which runs the catalog's rules over the AWS parts below. Proven by its own test, not the shared suite: the client against the API's handler gives the local catalog's answers. Three operations run only on one machine (rerunning reviews, rebuilding the index, the stored reviews).

Not proven yet no shared suite runs on both sides' adapters, so swapping a side isn't shown to work.

outbox

SQLite · same commit

An event saved with each version, in the same transaction, then delivered to search.

Plugs into Events, as Events

Code core/src/local/outbox.ts

events

stream → queue → indexer

In AWS the function's Events adapter delivers nothing itself (deliveredByTheStream): each version's event is written in the same DynamoDB transaction, and the table's stream carries it through a pipe into a queue, where the indexer reads it and rewrites the search file. That path runs outside the Events contract, so it isn't swapped with it.
